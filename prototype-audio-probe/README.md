# 音频探针（一次性验证工具）· 第 4 版

> 丢弃型原型，不是产品代码。验证完整个文件夹可以删掉。

## 第 1 版为什么失败

第 1 版想"偷听"YouTube 播放器发出的音频请求来拿地址。实测失败，原因不是代码写错，
而是 YouTube 网页版已经整体切换到 **SABR（服务端自适应码率）**：
格式列表里 12 个音频格式，**0 个带地址、0 个带加密串**，播放器改用私有协议取流。

这一点在命令行侧独立复现过，和探针报的完全一致。

## 第 3 版结果：音频链路全通

扩展环境里步骤 0–6 全部成功，时间轴误差 0.00 秒。只有最后送 Groq 那步回了 500。

## 第 4 版换了什么

500 是服务端内部错误，不是参数不对。怀疑是切片继承了整个视频的时长声明
（切片实际 609 秒，头部却写着 2336 秒），但本地试了改时长字段和剔索引表都没能对上。

与其继续猜，这一版让探针**一次测 4 种格式**，用数据确定哪种可用：

1. 原样 m4a 切片（和上次一样，排除偶发错误）
2. 短切片 30 秒 m4a（排除大小/时长因素）
3. 剔掉 sidx 索引表的 m4a
4. 转成 16kHz 单声道 WAV

第 4 种最稳：本地解码后重新编码，容器最简单。Whisper 内部就是 16kHz 单声道，
所以不损失识别质量。

四次调用总成本约 0.005 美元。

## 第 2 版为什么失败

方向对了，但请求发错了地方：扩展自己发出的请求带着 `Origin: chrome-extension://...`，
YouTube 接口直接回 403。命令行用完全相同的请求内容测是 200，差别只在这个头。
浏览器不允许扩展伪造 Origin。

## 第 3 版换了什么

把接口请求挪进**网页自己的环境**里发（`world: "MAIN"`），Origin 自然就是
`https://www.youtube.com`。张睿的代码里已经在用同一个手法读播放器信息。

另外音频下载也加了自动兜底：扩展直接下载失败时，自动改从网页环境下载重试，
不会再因为一个权限问题就整条链路断掉。

## 第 2 版换了什么

不再从网页版拿地址，而是**换一个客户端身份**去问 YouTube 官方接口。
网页版走 SABR，但 VISIONOS / IOS 这类客户端仍然返回普通直连地址，且不需要签名解密。

需要的只是页面里的一个匿名会话标识 `visitorData`——扩展从页面直接读得到。

**不使用你的 YouTube 登录 Cookie**（代码里写死 `credentials: "omit"`），
只用匿名标识，避免把这些请求和你的账号绑在一起。

## 怎么用

1. 到 `chrome://extensions` 找到「音频探针」，点**重新加载**（重要，代码变了）
   - 第一次装：开「开发者模式」→「加载已解压的扩展程序」→ 选这个文件夹
2. 打开一个 YouTube 视频页面
3. 点工具栏「音频探针」图标
4. （可选）粘贴 Groq API Key，会真跑一次识别并打印字幕
5. 点「开始验证」

这次**不需要先播放视频**了。

## 步骤

| 步骤 | 验证什么 |
|---|---|
| 1 | 从页面读到匿名会话标识 visitorData |
| 1.5 | 换客户端身份要直连地址（VISIONOS，失败退到 IOS） |
| 2 | 分段下载拿到的是不是裸音频 |
| 3 | 读出 sidx 索引表（时间 → 字节对照表） |
| 4 | 并行分段下载速度 |
| 5 | 纯字节拼接切出一段（不用 ffmpeg） |
| 6 | 切片能不能解码出声音 |
| 7 | Groq 返回带时间戳的字幕 |

## 关于 API Key

只存在于弹窗输入框，不落盘、不进日志，除 Groq 官方接口外不发去任何地方。
关掉弹窗就没了。留空也能验证前 6 步。
